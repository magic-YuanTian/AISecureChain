## 1. MITRE ATLAS Integration

[MITRE ATLAS](https://atlas.mitre.org) is the ATT&CK-style framework for **AI/ML
attacks**. Today we analyzed it, designed how it folds into our ontology, and
wired the visualization layer for it.

### What ATLAS adds that we didn't have
Our vulnerability taxonomy already had three layers — **CWE** (what weakness),
**AVID** (which AI lifecycle domain), and **CVSS** (severity). ATLAS adds a
fourth that none of those capture: **how an attacker actually exploits an AI
system.** Examples with no CWE/AVID equivalent:

- Prompt Injection (direct / indirect / triggered)
- LLM Jailbreak
- Craft Adversarial Data (white-box / black-box / backdoor trigger)
- Poison Training Data, Publish Poisoned Models
- Model Stealing via Inference API, Extract LLM System Prompt
- **RAG-specific** attacks (Gather RAG-Indexed Targets, Retrieval Content Crafting)
- **Agent** attacks (AI Agent Tool Invocation, LLM Prompt Self-Replication)

### Data analyzed
Pulled the official ATLAS dataset: **16 tactics, 170 techniques** (with
subtechniques), plus **mitigations** and **case studies**.

### Designed ontology expansion (additive — nothing removed)
Mirrors our existing `VulnerabilityType` (CWE) pattern exactly:

| New class | Role | DB table (mirrors `vulnerability_type`) |
|---|---|---|
| `AttackTactic` | the 16 lifecycle phases | `attack_tactic` |
| `AttackTechnique` | the ~170 techniques + subtechniques | `attack_technique` |
| `Mitigation` | countermeasures (new dimension) | `mitigation` |
| `CaseStudy` *(optional)* | real-world attack campaigns | `case_study` |

New relations (junction tables, like `vulnerability_is_a`):
`exploitedVia` (Vulnerability→Technique), `achievesTactic` (Technique→Tactic),
`subtechniqueOf`, `mitigates`, `remediates`.
Plus two attribute expansions on `Software`: `model_family`, `model_access_level`
(black/grey/white-box — central to ATLAS's "AI Model Access" tactic).

### Integrated into the product today
- **Knowledge-graph visualization** now recognizes four ATLAS node types —
  **Attack Technique, Attack Tactic, Mitigation, Case Study** — with dedicated
  colors, **filter pills, and legend entries**. The graph is ready to render
  ATLAS nodes the moment the data is seeded.

### Pending (next steps to speak to)

  (modeled on the existing `import_avid.py`).
- DB schema + ontology `CLASS_HINTS` so the extraction LLM emits `exploitedVia`

## 2. End-to-End Example — the system *discovers and names* a new vulnerability

**Goal:** show the system reading a real-world write-up of a **novel AI attack that
has no CVE / GHSA / any official identifier**, deciding it is a genuine
vulnerability, **minting its own vulnerability ID + description**, and wiring it
into the knowledge graph. This is the knowledge base acting as a *discovery*
tool — not just re-indexing the CVE feed.

**Source:** Johann Rehberger's research write-up
**["ZombAIs: Prompt Injection to Take Over Claude Computer Use"](https://embracethered.com/blog/posts/2024/claude-computer-use-c2-the-zombais-are-coming/)**.
It documents an **indirect prompt-injection** attack that tricks Anthropic's
**Claude Computer Use** into downloading and running the **Sliver** C2 implant —
turning an autonomous AI agent into a remote-controlled "ZombAI." There is **no
CVE** for this; it is a brand-new *attack technique*, exactly the class of AI risk
that the CVE feed misses and that **MITRE ATLAS** (Section 1) is built to capture.

### New capability built for this: minting vulnerability IDs
Previously the pipeline **dropped** any finding without an official id
(`skipped_no_id`) — so novel, un-cataloged AI attacks were lost. We added:

- **Synthetic ID minting** (`merger.py::mint_vuln_id`). A finding with a clear
  title but no official id gets a stable internal id **`AISC-YYYY-XXXXXX`**
  (AISecureChain + year + short hash of the finding title). The hash makes it
  **deterministic and idempotent** — re-ingesting the same disclosure resolves to
  the same id instead of creating a duplicate. The `source` URL is stored for
  provenance, and the `AISC-` prefix self-identifies these as system-discovered.
- **Over-extraction collapse.** Chunk-level LLM extraction split this single
  finding into 3 near-duplicate vulnerabilities (one per section). A new merge
  pass folds minted findings that target the **same affected software** into one
  central finding (richest description wins), so a single disclosure yields a
  single clean record. Findings carrying real CVE/GHSA ids are never collapsed,
  so multi-CVE roundups stay separate.

### Before → After

| | Before | After |
|---|---|---|
| `AISC-` (minted) vulns in DB | **0** | **1** |
| Total vulnerabilities | 3,775 | 3,776 |
| "Claude Computer Use" software | absent | present (vendor: Anthropic) |
| The ZombAIs attack in the KG | nothing | a fully linked node (below) |

The pipeline (crawl → chunk → LLM extract → **mint** → merge/collapse → validate →
persist) produced, with zero manual entry:

```
Anthropic ─produces→ Claude Computer Use ─AFFECTS→ AISC-2026-7AEC83 ─is-a→ CWE-1427
```

- **`AISC-2026-7AEC83`** — *"Prompt injection enabling command and control (C2)"*
- **Description** (auto-written): "Claude Computer Use was tricked into downloading
  malware, executing it, and joining a Command and Control (C2) server via a
  prompt injection attack."
- **Weakness:** auto-mapped to **CWE-1427** — *Improper Neutralization of Input
  Used for an LLM Prompt* (the new prompt-injection CWE), because the source names
  the technique explicitly.
- **Provenance:** the blog URL is stored on the record.

### Why it matters (the talking point)
An analyst pastes a URL for a brand-new AI attack that **exists in no vulnerability
database**. The system recognizes it as a real finding, **assigns it a citable
internal ID**, writes a description, classifies the weakness, and connects it to
the affected vendor/product — making a previously-uncatalogued AI threat
queryable alongside formal CVEs. This is how the knowledge base stays ahead of
the slow official-CVE process for emerging AI attacks.

### Two consolidation bugs fixed earlier (still in place)
1. **`persist.py` — orphaned link.** `vulnerableTo` wrote a *software* id into the
   `sw_version_id` column. **Fix:** when a Software is linked directly (no version
   in the source), materialize a placeholder version — which is exactly what lets
   `Claude Computer Use ─AFFECTS→ AISC-2026-7AEC83` form here.
2. **`dedup.py` — duplicate software.** A vendorless extraction didn't match an
   existing vendor-bearing row. **Fix:** fall back to an unambiguous name-only
   match when the incoming record has no vendor.

All 16 merger/persist tests pass (incl. new tests for minting + determinism).
*(An earlier run also demonstrated official-CVE enrichment — ingesting
`CVE-2025-61620`, a vLLM Jinja DoS, and reusing the existing vLLM product without
duplication. The minting example above is the more powerful story.)*

> Repro: `python3 run_demo_extract.py "https://embracethered.com/blog/posts/2024/claude-computer-use-c2-the-zombais-are-coming/" --persist`
> (`run_demo_extract.py` swaps the crawler for `requests`+`markdownify` since
> `crawl4ai` isn't installed in this environment; all other stages are the real pipeline.)

## 3. Other Updates

### Knowledge-graph visualization
- **Light theme.** Canvas changed from near-black to light with a subtle dotted
  grid; every overlay control (search, filter pills, zoom, legend) re-skinned to
  a light "glass" style.
- **Readability.** Nodes now have crisp white outlines + a focus halo; labels get
  a translucent pill so they stay legible over edges; links tuned for contrast.

### Data-quality: "underspecified" nodes
- Diagnosed that **~30% of all version nodes (1,580 of 5,268)** were meaningless
  placeholders (`unspecified`, `0`, `*`, `n/a`) created when sources don't state
  an affected version (common for AI models).
- **Collapsed** them in the graph view: Software now links **directly** to the
  Vulnerability via an `AFFECTS` edge instead of a swarm of identical
  "unspecified" dots. Data is untouched — purely a cleaner view.

### Extract tab (UI)
- **Consolidation transparency.** Renamed "Merge into DB" → **"Consolidate"**, and
  added a summary panel showing exactly what happened: **Added** (new rows) /
  **Reused** (matched existing) / **Links created**, plus **"Where it landed"**
  links straight to each `/vuln/<id>` page and the graph.
- **Persistent expand/collapse.** Multiple URL rows can stay open at once; each
  remembers its data across refreshes (collapsing no longer discards it).

### Query / Ontology tabs
- Removed the canned **example queries** from the Query tab.
- **Comprehensive column filtering** for the ontology data tables: a global
  all-column search **plus** per-column filters with type-aware controls —
  text *contains*, numeric **min/max**, date **from/to**, boolean Any/True/False,
  and **enum dropdowns** populated from real distinct values (facets). Filters
  combine with AND; backend filters span **all** records, not just the page.
- Replaced the old native `window.confirm` popups with a modern **in-app modal**.

### Reliability / debugging
- **Filters "did nothing" bug.** Root cause: the Flask backend runs with
  `debug=False` (no auto-reload), so the **stale process** was serving pre-change
  code and ignoring the new filter params. Restarted it via its keep-alive
  wrapper; verified filters/facets now work live.
  ⚠️ *Note for the team:* any `app.py` change needs a backend restart to take effect.
- **Explorer zoom-reset bug.** Returning to the Explorer tab showed the graph
  unexpectedly zoomed in. Root cause: the camera restore ran before the canvas
  had real dimensions, and `ForceGraph2D` resets its zoom transform on dimension
  change — wiping the restore. **Fix:** gate the restore on valid dimensions and
  re-apply it on any size change, so zoom/pan now persists across tab switches.

### Docs
- Expanded `CLAUDE.md` (build/run/test commands, the **port 3509**, the frontend
  hard-coded API IP caveat, the evaluation harness, hard-coded LLM creds location,
  the dedup pattern, async pipeline note).
