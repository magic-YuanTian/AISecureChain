# RCE Flaw in AI-Assisted Coding Tool Poses Software Supply Chain Risk
A critical vulnerability in the trust model of Cursor, a fast-growing tool for LLM-assisted development, allows for silent and persistent remote code execution.

A flaw in the trust model of a popular artificial intelligence (AI)-powered development environment can allow a malicious actor to modify already approved code extensions for a project and conduct persistent remote code execution (RCE), posing a threat to the modern software supply chain.
Researchers at Check Point Research uncovered the critical vulnerability — dubbed "MCPoison" and tracked as CVE-2025-54136 — in Cursor, which uses large language model (LLM)-driven automation to accelerate software development. The flaw is related to how Cursor has configured its Model Context Protocol (MCP), an aspect of the system that lets developers automate workflows, according to [a report published today](https://research.checkpoint.com/2025/cursor-vulnerability-mcpoison/).
The problem exists because once [an extension](https://www.darkreading.com/application-security/researchers-warn-of-easily-exploitable-spoofing-bug-in-visual-studio) is approved via the MCP, someone can surreptitiously modify it without any further user interaction, providing a surface that "enables persistent, silent, and remote code execution in any Cursor-based development environment," Check Point Research's Andrey Charikov, Roman Zaikin, and Oded Vanunu wrote in the report.

"Once an MCP is approved, the attacker can repeatedly inject malicious commands without user awareness," they wrote.
An attacker with write access to a shared repository can perform a host of malicious actions with this kind of trusted access to the development environment, the researchers noted. These include maintaining ongoing remote access by embedding a reverse shell into an MCP configuration and executing arbitrary local commands silently every time the victim opens Cursor.
Attackers can use the flaw to escalate privileges within the user context, which is especially dangerous on developer machines with cloud credentials or source code access. They can also persist in the environment indefinitely, as the malicious MCP is re-executed on every project launch or repository sync, the researchers wrote.
## Disclosure and Mitigation
Check Point Research disclosed the issue to the Cursor development team on July 16, and the team issued an update to the platform, version 1.3, on July 29. Though the notes for that release did not mention the vulnerability, Check Point has confirmed in independent testing that [the issue](https://www.darkreading.com/application-security/llms-ai-generated-code-wildly-insecure) "has been effectively addressed," according to the report.
"Now, any change to an MCP configuration — including something as small as adding a space — triggers a mandatory approval prompt," according to the report. "The user must explicitly approve or reject the modified MCP before it can take effect."
Check Point recommends that any organization using Cursor in their development environment update immediately to version 1.3 to fix the issue. This version also fixes a prompt-injection flaw in Cursor's MCP discovered by Aim Labs, which was dubbed "CurXecute" and tracked as [CVE-2025-54135.](https://github.com/cursor/cursor/security/advisories/GHSA-4cxx-hrm3-49rm)
Related:[Attackers Exploit N-able Patch Bypass Flaw on RMM Servers](https://www.darkreading.com/vulnerabilities-threats/attackers-exploit-n-able-patch-bypass-flaw)
That flaw, revealed last week, exists because Cursor runs with developer-level privileges that can be exploited when paired with an MCP server that fetches untrusted external data, [according to a blog post](https://www.aim.security/lp/aim-labs-curxecute-blogpost) by Aim Labs.
"By feeding poisoned data to the agent via MCP, an attacker can gain full remote code execution under the user privileges, and achieve any number of things, including opportunities for ransomware, data theft, AI manipulation and hallucinations, etc.," according to the post.
## New Risk Paradigm
Aside from being dangerous for an organization using Cursor, both flaws demonstrate a broader threat to the AI-assisted development pipeline, "where automation, convenience, and implicit trust can be exploited for long-term access to developer machines, credentials, and source code," Check Point researchers wrote.
Vanunu, Check Point's chief technologist and head of product vulnerability research, said in an emailed statement that overall, these [AI-powered developer tools](https://www.darkreading.com/application-security/next-gen-developers-cybersecurity-powder-keg) represent a new reality for organizations. Though they offer unprecedented modern convenience for developers in how they help them build software, they also [introduce attack surfaces](https://www.darkreading.com/application-security/will-ai-code-generators-overcome-their-insecurities-2025) that organizations have never seen before, he said. This will require a mindset change for defenders.
